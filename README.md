# phoU 워킹 프로토타입 (시안)

팀 광명의 사진공유 앱 **phoU**의 전체 화면 흐름을 폰에서 눌러볼 수 있게 만든 시안이다.
모임·여행·행사에서 많은 사진을 여러 사람과 나눠야 하는 사람 대신, 사진을 고르고 공유하는 귀찮은 일을 줄이는 것이 목표다.

- 배포 주소: https://phou-prototype.vercel.app
- 캡스톤 디자인 5주차(10/5–10/11), 확정·검증 단계 결과물

## 화면 흐름

**호스트 (앱)**
홈 → 이벤트 공유폴더 만들기(이름·기간·내 사진 공유 옵션·링크 유효기간·비밀번호) → QR 생성 → 공유하기

**참여자 (웹, 앱 설치 없음)**
QR·링크로 입장 → 내 사진 공유 옵션 선택 → 얼굴 등록(선택) → 공유폴더

**공통**
공유폴더(비슷한 사진 묶음의 베스트컷, 전체 / 내가 나온 사진 / 장소별) → 묶음 상세(다른 컷 보기, 베스트컷 바꾸기, 저장)

화면 위의 시연 메뉴로 아무 화면이나 바로 이동하고, 로딩·비어 있음·기간 지남 같은 상태를 바꿔 볼 수 있다.

## 효과가 있었던 핵심 프롬프트

1. **조건을 먼저 못박기**
   > 이벤트 공유파일 생성 화면 하나만 만들어줘. … 상태: 로딩 / 비어 있음 / 기간 지남을 반드시 포함할 것. 기술: HTML+CSS+JS 단일 파일, 외부 라이브러리 없이. 색: 배경 FAFBFF, 강조 메인 1색과 서브 1색만. 그라데이션 금지. 다른 화면은 만들지 마.

   상태와 색 규칙을 처음부터 적어 두니, 이후 화면을 늘려도 같은 규칙이 유지됐다.

2. **바로 만들게 하지 않고 먼저 의논하기**
   > (유저플로우와 화면 설명 전체를 주고) 이것을 바탕으로 워킹 프로토타입을 만들어야해. 나랑 충분히 의논해서 효율적으로 워킹 프로토타입을 만들어보자

   AI가 바로 만들지 않고 정해야 할 질문 6개를 먼저 꺼냈다. 그중 '웹 참여자는 사진 자동 업로드가 안 된다'는 지적은 기획 단계에서 놓친 부분이었다.

3. **질문에 내 결정으로 답하기**
   업로드 방식, 호스트와 참여자 옵션의 관계, 얼굴 등록 여부, 링크 만료·비밀번호 유지, 예시 그림 사용을 직접 정해서 전달했다. AI가 추천한 '호스트 옵션을 참여자 기본값으로 쓰기'는 버리고, '각자 자기 사진 옵션만 정하고 서로 바꿀 수 없다'는 규칙을 새로 정했다.

## 실패한 시도

- **화면을 하나씩 요청한 것**: 만들기 화면 다음에 홈만 따로 요청했더니, 하단 탭이 우리 유저플로우와 다른 구성(갤러리·친구·설정)으로 나왔다. 전체 흐름과 화면 설명을 한 번에 주는 방식으로 바꿨다.
- **기획의 자동 업로드**: 참여자도 기간 중 사진이 자동으로 올라가게 기획했지만, 웹 브라우저는 사용자가 직접 고른 사진만 읽을 수 있다. 앱은 자동, 웹은 직접 올리기(기간 밖 사진은 촬영 시간으로 자동 제외)로 설계를 바꾸고, 프로토타입에서는 자동 업로드를 연출만 했다.
- **클로드 안에서만 돌아가던 시안**: 처음 만든 시안은 클로드 계정이 없으면 열 수 없어서 수업에서 같이 돌릴 수 없었다. GitHub에 올리고 Vercel로 배포해 해결했다.
- **커밋 기록**: 첫 버전은 웹 업로드로 파일 하나를 한 번에 올려서 작업 과정이 커밋에 나뉘어 남지 않았다. 이후부터는 바꾼 내용을 커밋 메시지에 적는다.

## 남은 한계

- 두 폰은 데이터를 주고받지 않는다. 다른 폰으로 QR을 찍으면 내가 만든 폴더 대신 예시 폴더가 보인다.
- 베스트컷 추천, 얼굴 인식, 장소 분류, 자동 업로드는 실제로 동작하지 않고 정해진 결과를 보여주는 연출이다.
- 사진은 실제 사진이 아닌 예시 그림이다. 그래서 '고르는 시간이 줄었는지'는 아직 측정할 수 없다.
- 홈과 다른 화면 사이의 이동이 더 쉬워야 한다.
- 갤럭시 브라우저와 다른 폰으로 QR 스캔하는 것은 아직 확인하지 못했다.

## AI가 만든 부분

코드 전체, 화면 문구 대부분, 사용성 테스트 문서 초안은 Claude가 만들었다.
기능 규칙, 유저플로우, 색 규칙, 화면 구성에 대한 결정은 팀 광명과 내가 했다.
PRD와 유저플로우는 팀 광명이 작성했다.
