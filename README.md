# phoU 워킹 프로토타입 · AlbumZip 디자인 시안

팀 광명의 사진공유 앱 **phoU**의 전체 화면 흐름을 폰에서 눌러볼 수 있게 만든 시안이다.
모임·여행·행사에서 많은 사진을 여러 사람과 나눠야 하는 사람 대신, 사진을 고르고 공유하는 귀찮은 일을 줄이는 것이 목표다.

- 워킹 프로토타입: https://phou-prototype.vercel.app
- AlbumZip 디자인 시안(v10): https://phou-prototype.vercel.app/albumzip/
- 캡스톤 디자인 5주차(10/5–10/11) 확정·검증 단계 결과물, 디자인 시안은 10/23–10/24 개인 작업

## 화면 흐름

**호스트 (앱)**
홈 → 이벤트 공유폴더 만들기(이름·기간·내 사진 공유 옵션·링크 유효기간·비밀번호) → QR 생성 → 공유하기

**참여자 (웹, 앱 설치 없음)**
QR·링크로 입장 → 내 사진 공유 옵션 선택 → 얼굴 등록(선택) → 공유폴더

**공통**
공유폴더(비슷한 사진 묶음의 베스트컷, 전체 / 내가 나온 사진 / 장소별) → 묶음 상세(다른 컷 보기, 베스트컷 바꾸기, 저장)

화면 위의 시연 메뉴로 아무 화면이나 바로 이동하고, 로딩·비어 있음·기간 지남 같은 상태를 바꿔 볼 수 있다.

## AlbumZip 디자인 시안 (개인 AI 활용)

워킹 프로토타입의 흐름 위에 시각 디자인을 입힌 시안이다. 픽셀 아트·회색 바탕·형광 포인트를 컨셉으로, 화면 12종과 스타일보드를 만들었다.

- 키워드: 픽셀 아트·게임, 강한 포인트 컬러(초록 = 행동·선택, 핑크 = 맘찍), 싸이월드 감성(앨범마다 폴더 스킨)
- 화면: 첫 홈, 내 공유 앨범, 앨범 정보, 스킨 고르기, 초대, 전체 + 필터, 베스트컷, 맘찍, 장소별, 스킨 바꾸기
- 버전: v1–v11 (여기 배포한 것은 회색 바탕 v10, 이후 흰 바탕 v11까지 진행)

| --- | --- |

| v5 | 폴더 세트 3종(새 12 · 기존 16 · 섞은 28), 핑크 캐릭터 컨셉 수정 |

## 효과가 있었던 핵심 프롬프트

### 워킹 프로토타입

1. **조건을 먼저 못박기**
   > 이벤트 공유파일 생성 화면 하나만 만들어줘. … 상태: 로딩 / 비어 있음 / 기간 지남을 반드시 포함할 것. 기술: HTML+CSS+JS 단일 파일, 외부 라이브러리 없이. 색: 배경 FAFBFF, 강조 메인 1색과 서브 1색만. 그라데이션 금지. 다른 화면은 만들지 마.

   상태와 색 규칙을 처음부터 적어 두니, 이후 화면을 늘려도 같은 규칙이 유지됐다.

2. **바로 만들게 하지 않고 먼저 의논하기**
   > (유저플로우와 화면 설명 전체를 주고) 이것을 바탕으로 워킹 프로토타입을 만들어야해. 나랑 충분히 의논해서 효율적으로 워킹 프로토타입을 만들어보자

   AI가 바로 만들지 않고 정해야 할 질문 6개를 먼저 꺼냈다. 그중 '웹 참여자는 사진 자동 업로드가 안 된다'는 지적은 기획 단계에서 놓친 부분이었다.

3. **질문에 내 결정으로 답하기**
   업로드 방식, 호스트와 참여자 옵션의 관계, 얼굴 등록 여부, 링크 만료·비밀번호 유지, 예시 그림 사용을 직접 정해서 전달했다. AI가 추천한 '호스트 옵션을 참여자 기본값으로 쓰기'는 버리고, '각자 자기 사진 옵션만 정하고 서로 바꿀 수 없다'는 규칙을 새로 정했다.

### AlbumZip 디자인 시안

4. **수정 사항을 번호로 묶어 한 번에 주기**
   > 1. 하단 바 삭제 2. 앨범 필터 드롭다운(전체·베스트컷·찍은 사람·사람별·장소별·시간대별·음식·풍경), 베스트컷은 포인트 컬러 3. '공유 앨범' 용어 통일 4. 만들기 화면 기간은 시작 필수·종료 선택, 장소·자동 불러오기·비밀번호

   참고 이미지와 함께 한 번에 주니 화면 여러 개가 같은 기준으로 한꺼번에 바뀌었다.

5. **고치기 전에 방향만 먼저 받기**
   > 사진이 들어가니 안 어울려. 컨셉은 유지하면서 어울리게 할 방향만 제안해 줘

   바로 고치게 하지 않고 제안(사진 둘레 흰 벽, 픽셀 모서리, 라벨 줄이기, 대비 수정)을 먼저 받아 비교한 뒤 "일단 반영해서 수정해 줘"로 진행했다.

6. **세 버전으로 비교하기**
   > 새로 뽑은 폴더 이미지들인데, 얘네 버전으로 하나, 기존 폴더 이미지 버전으로 하나, 둘 다 들어간 거 하나 이런 식으로 뽑아줘

   같은 화면에 스킨만 다른 보드 3개를 나란히 보고 섞은 28종을 최종안으로 골랐다.

## 실패한 시도

### 워킹 프로토타입

- **화면을 하나씩 요청한 것**: 만들기 화면 다음에 홈만 따로 요청했더니, 하단 탭이 우리 유저플로우와 다른 구성(갤러리·친구·설정)으로 나왔다. 전체 흐름과 화면 설명을 한 번에 주는 방식으로 바꿨다.
- **기획의 자동 업로드**: 참여자도 기간 중 사진이 자동으로 올라가게 기획했지만, 웹 브라우저는 사용자가 직접 고른 사진만 읽을 수 있다. 앱은 자동, 웹은 직접 올리기(기간 밖 사진은 촬영 시간으로 자동 제외)로 설계를 바꾸고, 프로토타입에서는 자동 업로드를 연출만 했다.
- **클로드 안에서만 돌아가던 시안**: 처음 만든 시안은 클로드 계정이 없으면 열 수 없어서 수업에서 같이 돌릴 수 없었다. GitHub에 올리고 Vercel로 배포해 해결했다.
- **커밋 기록**: 첫 버전은 웹 업로드로 파일 하나를 한 번에 올려서 작업 과정이 커밋에 나뉘어 남지 않았다. 이후부터는 바꾼 내용을 커밋 메시지에 적는다.

### AlbumZip 디자인 시안

- **빈 사진 자리로 만든 디자인**: 회색 사진 자리로 맞춘 화면에 실제 여행 사진을 넣자 색과 면이 부딪혔다. 사진 둘레에 흰 벽을 두고 라벨을 줄여 사진이 먼저 보이게 바꿨다(v8).
- **하단 버튼 두 종류**: 하단에 주요 버튼이 두 가지라 무엇을 눌러야 할지 헷갈렸다. 화면마다 주요 버튼을 하나로 줄였다(v9).
- **검정 버튼 통일**: 장소별 화면에서 지도 초록과 버튼 초록이 부딪혀 버튼을 검정으로 통일했더니, 이번엔 초록이 거의 사라졌다. 검정 버튼 안에 초록 아이콘을 두고, 초록은 지금·선택·완료에만 쓰는 규칙으로 정리했다(v10).
- **세부 그래픽**: Claude가 폴더 스킨 같은 세밀한 일러스트까지 원하는 수준으로 만들지는 못했다. 러프를 직접 그리고 이미지는 ChatGPT로 따로 만들어 넘기는 방식으로 바꿨다.

## 남은 한계

- 두 폰은 데이터를 주고받지 않는다. 다른 폰으로 QR을 찍으면 내가 만든 폴더 대신 예시 폴더가 보인다.
- 베스트컷 추천, 얼굴 인식, 장소 분류, 자동 업로드는 실제로 동작하지 않고 정해진 결과를 보여주는 연출이다.
- 워킹 프로토타입의 사진은 실제 사진이 아닌 예시 그림이다. 그래서 '고르는 시간이 줄었는지'는 아직 측정할 수 없다.
- 홈과 다른 화면 사이의 이동이 더 쉬워야 한다.
- 갤럭시 브라우저와 다른 폰으로 QR 스캔하는 것은 아직 확인하지 못했다.
- AlbumZip 디자인 시안은 화면을 한 장씩 보여주는 디자인 보드라 눌러서 넘겨 볼 수 없고, 워킹 프로토타입에 아직 합쳐지지 않았다.

## AI가 만든 부분

워킹 프로토타입의 코드 전체, 화면 문구 대부분, 사용성 테스트 문서 초안은 Claude가 만들었다.
기능 규칙, 유저플로우, 색 규칙, 화면 구성에 대한 결정은 팀 광명과 내가 했다.
PRD와 유저플로우는 팀 광명이 작성했다.

AlbumZip 디자인 시안의 HTML 디자인 보드와 화면 배치는 Claude가 만들었다.
컨셉·캐릭터·색 규칙과 버전마다의 수정 방향은 내가 정했고, 폴더 스킨 이미지(러프 직접 + ChatGPT), 여행 사진 촬영과 베스트컷 보정은 내가 했다.
